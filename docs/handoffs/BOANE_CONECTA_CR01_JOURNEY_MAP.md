## Plano de contas e dados QA

Preparar, por processo administrativo **já autorizado**, CITIZEN A, CITIZEN B, SUPER_ADMIN, ADMIN, MANAGER, EDITOR, EMPLOYEE, com credenciais descartáveis distintas; confirmar papéis reais via `/auth/me`. Não há endpoint interno de provisionamento demonstrado; se não existir processo aprovado, marcar actor BLOCKED. `POST /auth/register` cria apenas CITIZEN. Usar serviços/formulários e documentos fictícios expressamente aprovados, com IDs de fixture e lifecycle anotados localmente; sem SQL direto nem mutações QA antes de autorização. Cada jornada exige sucesso, negativos 401/403/404/409, isolamento por proprietário, tratamento de loading/erro e teclado/zoom. Limpar exclusivamente os próprios dados descartáveis se autorizado e houver API segura; nunca limpar volumes ou dados de outros.
